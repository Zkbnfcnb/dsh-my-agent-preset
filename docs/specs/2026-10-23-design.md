# 设计规范: 2026-10-23 dsh-my-agent-preset 三项优化（复制 / 运行时上下文快照 / UI 对齐）

## 背景与动机

当前插件（自定义预设模式）已支持：卡片网格 + 新增/编辑/启停/删除、提示词三种注入方式、技能白名单、工具范围、运行时自检、导出预设列表。用户提出三项优化：

1. 每张预设卡片新增「复制」动作：改 id、名字加「（复制）」编号，作为新预设入列表。
2. 把「snapshot 提示词注入」（= DSH 运行时上下文快照，`Current runtime context. This snapshot supersedes earlier runtime-context snapshots.` 那一段）做成像工具一样可选。
3. UI 与现有页面保持一致。

经四轮拷问确认全部决策，本文档为唯一实现依据。

## 关键事实（已核对官方代码，非推测）

- 快照文本 = `joinContextSections(renderContextSections(assembly.contexts))`（`dsh-system-prompt/lib/index.js`）。`assembly.contexts` 是**独立于 `sections` 的字段**：`complete: true` 与 `official-only` 都只动 `sections`，**不动 `contexts`** → 现状下无论哪种注入方式，快照都全量注入。
- 快照由 `dsh-agent-loop` 的 `RuntimeContextProjection.project()` 作为 **user/message** 注入会话，每步用 `refreshContext()` 重算。
- **required 项关不掉**：`assemble()` 与 `refreshContext()`（`dsh-system-prompt/lib/index.js:329-344`）会把 `required === true` 的 context 强制补回。官方 required 项：`working-directory:current`、`team:identity`。非 required 项从 `assembly.contexts` 移除后**不会被补回** → 可真正屏蔽。
- `working-directory:current` 额外在 waterfall（`dsh-working-directory/lib/index.js:48-61`）`prepend` 里 `unshift` 兜底。
- 过滤点选择：`system-prompt/assemble` waterfall 监听器。工具屏蔽（assemblyFilter）已证实可在 **Agent ctx** 上生效（见 README/`index.js:918`）。本设计把 contexts 过滤同样放在 **Host 侧 `installAgentScope` 的 agent.ctx** 监听器，与工具过滤同处，便于运行时观测就地收集。

## 目标

- 核心目标：
  1. 卡片底栏新增「复制」，按已定规则生成副本并入列表。
  2. 编辑器新增独立分组「运行时上下文」，以勾选清单（白名单语义）逐项控制快照 context 的注入，机制/呈现对齐工具区。
  3. 三项新能力在 UI 上与现有 aps-* 体系、技能/工具区同构，中英双语文案。

- 成功标准：
  - 可观察行为（本期三项必验）：
    1. 点「复制」→ 新卡片紧接源预设之后；id 为新生成 `custom-xxxxxxxx`；名字 `源名（复制 1）`；其余字段与启停状态与源一致；整列 `order` 重写为文档下标，本页卡片顺序 = 新建会话预设列表顺序。
    2. 快照勾选保存后，「重新读取」自检显示「保留快照上下文 N / 已屏蔽 M」计数 + 两个名单；被屏蔽的非必需项在真实会话的运行时快照里确实不出现。
    3. required 两项（工作区、团队身份）复选框默认勾选且置灰不可取消，运行时永远注入。
  - 性能标准：过滤在 `system-prompt/assemble` waterfall 内做集合判断，单次 O(n)（n=快照项数，个位数）；不引入额外租约/IO；与现有 official-only 过滤同量级，无可感知延迟。不设具体耗时门禁。
  - 不可接受的结果（红线）：
    - 勾选保存后被屏蔽的官方非必需快照仍出现在模型提示词里。
    - 副本 id 与源相同，或副本名字与已有预设重名却未编号。
    - 新快照区出现新配色/新组件/与技能·工具区不同构的样式。
    - 副本卡片位置、名字、启停、快照屏蔽任一项偏离本文档已确认决策。

## 范围

### 范围内（本期一次做完）

- 数据模型：preset 新增 `contexts` 字段（字符串数组 = 允许注入的非必需 context 名单，语义见下）；`normalizePreset`/`toDefinition` 透传。
- Host：`installAgentScope` 安装 contexts 过滤 waterfall 监听器（仅当 `contexts` 字段存在）；运行时观测表收集实见 context 名；`list()` 返回 `meta.contextCatalog`；`inspect` 返回 `keptContexts`/`blockedContexts`/`contextSurfaceCount`；`save` 扩展 `insertAfter` 并重写全列 `order`。
- Client：卡片底栏「复制」按钮 + 副本组装/编号去重/`insertAfter`；「运行时上下文」分组勾选清单（含全选/清空/计数、required 禁用）；自检面板加快照计数与两个名单；快照变更并入自动重读；顶部 notice 反馈复制结果。
- 文案：`client.js` 内嵌 `zh`/`en` 补齐全部新键；`locale/*.json` 的 `meta.description` 同步提及「上下文」与「复制」。
- 测试：新增回归脚本；README 补两节。

### 范围外（反目标，本期明确不做）

- 复制不递归作用于子 Agent（只管选了该预设的会话 Agent 本身）。
- 复制 = 完全副本（含全部字段），不做「只复制基本信息/部分字段」。
- 复制不自动跳转编辑页（副本入列表，不打开编辑器）。
- 不做多选批量复制（只单卡片逐个复制）。
- 屏蔽不回改已注入到会话历史里的旧快照消息（不改 session log）。
- 导出预设列表仍是 `id/name/description` 三字段，不加快照字段（不外泄）。
- 不改动 DSH 官方插件的 context 注册（只在预设层过滤 `assembly.contexts`）。
- 不做快照模板/跨预设共享配置。
- 空数组例外不做（严格白名单，见决策）。
- 不要求可量化耗时门禁。

## 已确认决策链

### 决策 1：复制按钮位置
- 原始问题：「在每个预设卡片停用后新增一个复制功能」中「停用后」指？
- 用户的回答：「停用」按钮之后（位置）——底栏顺序 id → 停用/启用 → 复制 → 删除；卡片无论启用/停用都显示复制。

### 决策 2：副本 id 与名字规则
- 原始问题：副本 id 与名字按哪种规则生成？
- 用户的回答：id 全新生成 `custom-xxxxxxxx`（与源无关联）；名字 = 源名 +「（复制）」；重名自动编号去重。

### 决策 3：编号起点与副本状态（用户答「2 和 3」）
- 原始问题：名字编号从几开始？副本启用状态怎么定？
- 用户的回答：首次就带编号「（复制 1）」，第二次「（复制 2）」，规则统一；副本启用状态跟随源预设（源停用→副本停用）。

### 决策 4：snapshot 所指
- 原始问题：需求 2 的「snapshot 提示词注入」是指运行时上下文快照吗？
- 用户的回答：是——即每轮注入的 `Current runtime context...` 那段（工作区/沙箱策略/审批策略/GUI URL/委派深度等），逐项可选注入。

### 决策 5：功能对齐档位
- 原始问题：snapshot 注入选项要对齐到什么程度？
- 用户的回答：只要勾选清单（白名单语义，勾上=注入，与技能区一致），不做「全部/白名单/排除」三模式，不做过滤搜索框。

### 决策 6：默认值与向后兼容
- 原始问题：新建/旧预设的默认勾选怎么定？
- 用户的回答：默认全选 = 现行为不变；字段缺失视为不管理（全量注入）；新预设初始全勾。

### 决策 7：required 项呈现
- 原始问题：关不掉的 required 快照项在清单上怎么呈现？

### 决策 8：清单来源

- 用户的回答：官方 7 项硬编码 + 运行时观测补充第三方/动态项（对齐工具区 per-Agent 观测表）。

### 决策 9：分组位置

### 决策 12：自检覆盖
- 原始问题：运行时自检面板要不要报告快照屏蔽结果？

### 决策 13：新出现项默认值
- 原始问题：数组里没有的「新快照项」默认按注入还是屏蔽？
- 用户的回答：未记录 = 默认屏蔽（严格白名单）。协调：字段**缺失**（旧数据）= 不管理 = 全量注入以保持行为；字段**存在**时数组即真相，未列项一律屏蔽（required 除外）。旧预设无需写盘迁移，直到用户在 UI 保存才转为「全勾的已管理」。
- 实现补充（机制核对后细化，已由回归验证）：旧预设**不做写盘迁移**——升级瞬间没人碰它，字段仍缺失，行为零变化。一旦在编辑器保存，Client 发送的是**面板实际展示的派生清单**（未管理 = 全勾 ∪ required），因此"所见即所存"；目录为空（Host 未提供）时保持原样不写空数组，避免意外把全部可选项屏蔽。未管理的源被复制时，副本也保持未管理。

### 决策 29：required 项能否改（第二轮追加，2026-10-23 上午）
- 原始问题：用户问「require 为 true 能改吗？」——决策 7 定的是「显示但禁用」，等于承认关不掉。
- 实测回答：DSH 三层强制注入（`assemble` required 通道、每步 `refreshContext()`、`dsh-working-directory` 自己的 `prepend` 修复监听器）。逐一验证四种方案：普通过滤（A）无效；只加 `prepend`（B）组装时删得掉、下一步被 `refreshContext` 复活；只同名覆盖（C）被修复监听器填回原文；**同名覆盖 + `prepend` 删除（D）两者叠加才真正关掉**，assemble 与 refresh 之后都不再出现。
- 用户的回答：做成**默认关闭的高级选项**（在「显示但禁用 / 完全不显示 / 允许勾但不保证生效」三选中选第一项的加强版）。
- 落地形态：required 行的**主复选框仍是只读呈现**（勾选 = 正在注入，禁用）；行下挂一个默认不勾的「高级 · 强制屏蔽这一项」，勾上才走 D；勾上后就地显示警告（依赖实现细节、DSH 升级可能静默失效；屏蔽当前工作区会让模型失去位置感）。取消勾选无需确认（只是恢复官方默认）。
- 数据模型相应细化：`contexts` **只写可选项名字**，必需项是否注入由新字段 `requiredSuppressed` 单独决定（缺失/空 = 契约保持）。`resolveContextSelection(surface, allowed, forced)` 第三参承载它，被强制屏蔽的必需项进 `blocked` 并另出 `forcedContexts`，页面标「已被本预设强制屏蔽」。
- 同时修掉两条实现缺陷：① `normalizeRequiredSuppression` 丢弃非必需名（否则可选项会被两个名单重复记账）；② 无 catalog 的降级路径下**不重写** `contexts` / `requiredSuppressed`（旧实现会从空视图重算出空数组，静默屏蔽掉该预设全部可选项——已加断言钉住）。

### 决策 30：能力协商（实现期追加）
- 触发事实：本轮实现后**实测到**「新 Client + 旧 Host」真实存在（Client 热更新，Host 需重启；期间 `list` 无 `capabilities`，旧 Host 会把 `requiredSuppressed` 静默丢掉）。给用户一个"勾了没反应"的复选框等于撒谎。
- 做法：Host 在 `list` 里声明 `meta.capabilities`；Client 据此门控——旧 Host 下**不渲染**高级勾选框，把文档里已存的屏蔽**读成"仍会注入"并标注原因**，保存时**原样透传**该字段（不新增屏蔽，也不抹掉用户既有意图，Host 升级后意图自动复活）。普通白名单与复制功能不受该门控影响。
- 与决策 25 的关系：那条讲的是「Host 完全没有快照概念」（连 catalog 都不给）时整块隐藏；本条讲的是「Host 有快照、但不认高级名单」时只门控高级勾选框。

### 决策 14：UI 一致含义（全选四项）
- 原始问题：「ui 要保持一致」具体覆盖哪几项？

### 决策 16：副本位置
- 原始问题：新副本在预设列表排哪里？
- 用户的回答：插在源预设之后。

### 决策 17：order 写法

- 决策 27：清单项排序 = 已勾选靠前 + 官方 order 升序 + 同 order 按名字，第三方观测项排末尾。
- 决策 28：快照勾选变动并入 `inspectKey`，350ms 防抖自动重读自检，与工具/技能一致。

### 决策 30：跟随运行时版本（第三轮追加，2026-11-06）

- 原始问题：`CONTEXT_CATALOG` 的 `required`/`order` 与 `OFFICIAL_SECTION_PREFIXES` 都是构建时抄下的表，只对某一版 DSH 成立——升级后要么锁死已经不需要的必需项，要么漏掉新版新增的必需项与官方命名空间。
- 机制核对（读 `dsh-system-prompt/lib/index.js` + `dsh-scope/lib/index.js`）：
  - `assemble()` 的 contexts 来自 `layers.merge(scope, layer => layer.contexts)`，`refreshContext()` 只补回 `required === true` 的项，`requiredContexts` 亦是注册表真值——因此“表的外面还有一张真值表”，且它就在服务实例上（`SystemPrompt.layers`）。
  - `resolveContext()` **不**把 `order`/`required` 带到组装结果里，所以从 `assembly.contexts` 读不到真值，必须读注册表。
  - 注册表**不保存 section 的归属**，没有任何 API 能回答“这是不是 DSH 注册的名字”——因此 `official-only` 无法改成正向归属判定。
- 落地：
  - 新增 `readContextRegistry()` / `readSectionNames()`（`layers.merge` 的 feature-detect 读取，失败即返回 undefined），store 按 preset 缓存视图，`system-prompt/change` 时失效；失败的读不缓存（服务异步挂载）。
  - `requiredContextNames(presetId)` / `contextOrders(presetId)` 优先真值、回退内置表；`resolveContextSelection` 增加第 4/5 参（required 集合、order 表），默认值保持旧行为。
  - `contextCatalog()` 每行新增 `source`（`registry`/`table`/`observed`）与 `present`，未知项标 `known:false`；注册表实存但从未被观测的名字也进入清单。
  - `normalizeRequiredSuppression` 不再按内置表裁剪（新版新增的必需项也要能强制屏蔽）；分区时仍按“运行时是否仍保护它”判定，非必需名保持惰性。
  - `official-only` 规则改为可扩展：`officialSectionPrefixes` / `officialSectionNames` / `officialSectionKeep` 三个可选字段随预设存、随 `toDefinition` 进 capability config；新增 `classifySections()` 与 `meta.officialFilter.suspect`，把“看起来像官方但不在规则内”的实存段报给页面。
  - 这组字段有页面入口（决策 31）：编辑器「注入方式」下方的三栏，只在 `official-only` 下渲染。
- 已知边界：`layers`/`merge` 非文档 API（只读、失败回退，不影响组装）；未记录 standing scope key 的预设退化为全局视图；官方段归属仍是命名空间契约。

### 决策 31：官方段规则的页面入口（第三轮追加，2026-11-06）

- 原始问题：决策 30 的规则字段只能手改数据文件，还踩到两个坑（页面保存会冲掉手写字段、`reload` 不重读文件）。
- 用户的回答：做进页面；**只在「只屏蔽官方」时显示**；字段为空数组或 undefined 时**自动填充 capability 的默认值**，不为空则展示存储值；UI 与现有表单一致。
- 实现要点：
  - Host：`meta.officialSectionDefaults` 暴露内置规则（`resolveOfficialRules(undefined)`），页面据此预填；`officialFilterReport(config, presetId)` 接受草稿规则与该预设的段表，`inspect` 返回按草稿算出的 `officialFilter`，所以改一栏就能看到漏检提示变化；`save` 继承未被提交的规则字段（更新从旧记录、复制从源），手写字段不再被页面保存抹掉；`reload` 改为 `load()` + `reconcile()`，真正重读数据文件。
  - Client：三栏复用 `Field` + `aps-input`（与名称/描述同款），每栏另带一行 `aps-example` 填写案例；`ruleText` 只承载输入中的原文（尾随逗号、半截命名空间），**不进存储**，`draft` 里放的是解析后的数组；解析接受 ASCII 逗号、全角逗号、换行，trim + 去重。
  - 修订（同日）：**不预填默认值**。空字段显示为空，内置默认写在框下的说明行（`officialDefaultsNote`），避免"没编辑过"看起来像"编辑过"；因此"删掉内置项"的提示只在框**非空**时出现——空框的语义是"用内置默认"，不是"我把它们都删了"。
  - 「空 = 内置默认」的语义不变：清空一栏写入 `[]`（不是 `undefined`），这样 Host 的 `carriedRules` 会被 payload 覆盖，`normalizePreset` 再把空数组丢弃 —— 用户清空即回到默认，而不是继承上一次的值。
- 已知边界：无法用这套 UI 表达“完全不屏蔽任何官方段”（空 = 默认）。要那个效果只能改内置表，属于有意取舍（配置项不允许把过滤器关掉）。

## 风险

- **技术风险：required 项关不掉。** 影响：无法实现「屏蔽工作区/团队身份」。缓解：UI 禁用其复选框并标注「必需 · 不可关闭」，过滤逻辑对 runtime 认定的 required 名恒定保留（决策 30 起读注册表真值，内置表仅作回退）。已在决策 7/13/30 处理。
- **版本风险：官方段命名空间漂移。** 影响：新版 DSH 新增命名空间后 `official-only` 静默漏过滤。缓解：规则可由预设字段扩展（决策 30），`meta.officialFilter.suspect` 在页面提示。仍无法自动发现，因为注册表不存归属。
- **技术风险：过滤监听器安装位置。** 影响：装错位置监听不到事件。缓解：与已证实可用的工具 assemblyFilter 同处（`installAgentScope` 的 `agent.ctx.on('system-prompt/assemble', ...)`，见 `index.js:918`），异常时降级不过滤（决策 24）。待验证：安装后在真实会话观察被屏蔽项是否消失（必验项 2）。
- **需求风险：严格白名单可能屏蔽第三方新能力。** 影响：字段存在时新观测项默认屏蔽。缓解：符合决策 13 用户明确选择；UI 显示观测到的第三方项为未勾选、可主动勾上。
- **兼容风险：字段缺失 vs 空数组语义。** 影响：混淆会导致旧预设被静默全屏蔽（偏离必验 2）。缓解：`normalizePreset` 仅在 `Array.isArray(input.contexts)` 时写入数组，否则保持 `undefined`（= 不管理 = 全量注入），过滤监听器仅对 `Array.isArray` 为真时安装。
- **环境风险：`order` 重写覆盖手工值。** 影响：若用户曾手工设 order，复制操作会重写全列。缓解：决策 17 用户明确选择该方案，本页无其它 order 编辑入口，可接受。
